# ポスターナビ

選挙ポスターの掲示場を、**できるだけ短い道のりで回る順番**を探す Web アプリです。スマホのブラウザで開き、ホーム画面に追加すると、アプリのように使えます。

回る順番は「巡回セールスマン問題」（すべての地点を1回ずつ通って戻る、いちばん短い道順を探す問題）として計算します。

## できること

- **掲示場の一覧を CSV で取り込む**: 番号・掲示場名・緯度・経度（設置場所はあれば）。見出しの名前が違っても自動で割り当て、分からないときは画面で選べます。UTF-8・Shift_JIS に対応しています。
- **出発地点を決める**: 地図を押す、現在地を使う、緯度・経度を入れる、のどれかで決めます。
- **回り方を選ぶ**: 徒歩・自転車・車、1か所の作業時間、最後に出発地点へ戻るかどうか。
- **ルートを探す**: 一覧の順に回った場合と比べて、何%短くなったかも表示します。
- **人数で分ける**: 2〜20班に分けると、いちばん時間のかかる班ができるだけ短くなるように、出発地点のまわりを扇形に分けます。
- **巡回する**: 班ごとに「次の掲示場」を表示します。Google マップで案内する（次の10か所までまとめて渡せます）、貼ったら印をつける、残りを現在地から引き直す、ができます。
- **順番を送る**: 班の順番を、地図のリンクつきの文字にして、LINE などで送れます。
- **オフライン**: 一度開けば、電波がなくても開けます（地図は一度表示した範囲だけ）。
- **見本で試す**: 架空の掲示場24か所の見本が入っています。

## ルートの計算方法

`js/tsp.js` で計算します（Web Worker で動かすので、計算中も画面は固まりません）。

| 掲示場の数 | 方法 |
| --- | --- |
| 12か所以下 | 動的計画法（Held-Karp）で、**最短の順を厳密に**求めます |
| 13か所以上 | 最近傍法で作った順を、2-opt（2本の辺のつなぎ替え）と Or-opt（1〜3か所の移し替え）で縮め、さらに反復局所探索（ダブルブリッジで崩して縮め直す）を時間の許すかぎり（約2.5秒まで）繰り返します |
| 班に分けるとき | 全体を回る輪を作ってから、順番のまま区切ります。区切り方は、いちばん重い班（移動＋作業の時間）が最小になるように動的計画法で決め、班ごとに順番を縮め直します |

- 最後に出発地点へ戻らないときは、「どこで終えてもよい」道順として解きます。
- 参考にした掲示場巡回 PWA の方法（最近傍法＋2-opt）と比べると、乱数で作った100〜1,000か所で、道のりが6〜11%ほど短くなりました。

### 注意

- **距離は直線距離**です。実際の道のり（道路・川・一方通行）は考えていません。表示する道のりと時間は、直線距離の1.3倍を、徒歩4km/h・自転車12km/h・車20km/hで割った目安です。
- 13か所以上のときは、最短の順だという保証はありません（十分に短い順です）。

## データとプライバシー

- **一覧・出発地点・貼った記録は、この端末のブラウザの中（localStorage）だけに保存します。** サーバーには送りません。ブラウザのデータを消すと、すべて消えます。
- 端末の外とのやり取りは、次のとおりです。
  - **Google マップ**: 「案内」を押すと、目的地（と経由地）の位置が Google マップに渡ります。
  - **国土地理院**: 地図を表示するとき、見ている範囲の地図画像を取得します。
  - **unpkg**: 地図の部品（Leaflet）を取得します。
  - 「順番を送る」は、端末の共有機能かコピーを使います。送り先を選ぶまで、どこにも送りません。

## 地図と外部の素材

| 素材 | 使い方 | ライセンス・出典 |
| --- | --- | --- |
| [Leaflet](https://leafletjs.com/) 1.9.4 | 地図の表示（unpkg から版を固定し、改ざん検出つきで読み込む） | BSD-2-Clause |
| [地理院タイル](https://maps.gsi.go.jp/development/ichiran.html) | 背景地図（淡色地図・標準地図） | 出典: 国土地理院 |
| Google マップ | 案内のときに、目的地を渡してアプリを開くだけ（[Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)、API キー不要） | — |

## 掲示場データについて

このリポジトリには、**架空の見本データ（24か所）だけ**を入れています。実際の掲示場の一覧は、各自治体の選挙管理委員会が公開する資料やオープンデータから入手し、利用条件と出典の表示に従って取り込んでください。掲示場は選挙ごとに変わります。

## 使うときの注意

- **運転中は操作しないでください。** 停車してから、または同乗者が操作してください。
- 選挙での利用にあたっては、公職選挙法などのルールを守ってください。

## 開発

ビルドは不要です。ファイルをそのまま配信すれば動きます（位置情報とオフライン対応は HTTPS か localhost でだけ動きます）。

```bash
npm start   # http://127.0.0.1:8782
npm test    # 試験（Node 22 以上）
```

| ファイル | 中身 |
| --- | --- |
| `index.html` / `style.css` | 画面の枠と見た目 |
| `js/app.js` | 画面（準備・ルート・班ごとの巡回・地図・CSV の取り込み） |
| `js/tsp.js` | ルートの計算（巡回セールスマン問題・班分け） |
| `js/worker.js` | 計算を画面と別に動かす Web Worker |
| `js/plan.js` | 所要時間の見積もり・送る文字など |
| `js/core.js` | CSV の読み込み・列の割り当て・行の検査・Google マップの URL |
| `js/store.js` | 端末内の保存 |
| `sw.js` / `manifest.webmanifest` / `icons/` | オフライン対応とホーム画面への追加（アイコンは `tools/make-icons.mjs` で作成） |
