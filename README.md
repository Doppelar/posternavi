# ポスターナビ 小諸市

**長野県小諸市**の選挙ポスターの掲示場を、**道に沿った、できるだけ短い道のりで回る順番**を探す Web アプリです。スマホのブラウザで開き、ホーム画面に追加すると、アプリのように使えます。

- 公開先: https://posternavi.vercel.app
- 回る順番は「巡回セールスマン問題」（すべての地点を1回ずつ通って戻る、いちばん短い道順を探す問題）として計算します。
- 距離は、小諸市の道路データ（OpenStreetMap）で、**道に沿って**計算します。車は一方通行も守ります。

## できること

- **掲示場の一覧を CSV で取り込む**: 番号・掲示場名・緯度・経度（設置場所はあれば）。見出しの名前が違っても自動で割り当て、分からないときは画面で選べます。UTF-8・Shift_JIS に対応しています。
- **出発地点を決める**: 駅・役所・学校・公民館・地区名などの名前（「小諸駅」など）や、住所（「相生町3」など）で探せます。掲示場の名前や番号でも探せます。地図を押す、現在地を使う、緯度・経度を入れる、でも決められます。
- **終わる場所を決める**: 最後に出発地点へ戻るか、どこで終えてもよいか、別の終点（出発地点と同じ方法で決める）か。
- **回り方を選ぶ**: 徒歩・自転車・車、1か所の作業時間。
- **ルートを探す**: 道に沿った距離で解き、地図にも道に沿った線で描きます。一覧の順に回った場合と比べて、何%短くなったかも表示します。「道に沿った距離で計算する」を外すと、直線距離で計算します。
- **小諸市の外の確認**: 市の境界を地図に点線で描き、市の外にある掲示場や出発地点を知らせます。
- **人数で分ける**: 2〜20班に分けると、いちばん時間のかかる班ができるだけ短くなるように、出発地点のまわりを扇形に分けます。
- **巡回する**: 班ごとに「次の掲示場」を表示します。Google マップで案内する（次の10か所までまとめて渡せます）、貼ったら印をつける、残りを現在地から引き直す、ができます。
- **順番を送る**: 班の順番を、地図のリンクつきの文字にして、LINE などで送れます。
- **オフライン**: 一度開けば、電波がなくても開けます（地図は一度表示した範囲だけ）。
- **見本で試す**: 小諸市内の、架空の掲示場30か所の見本が入っています。

## ルートの計算方法

計算は Web Worker で動かすので、計算中も画面は固まりません。

### 道に沿った距離（`js/roads.js`）

1. 小諸市の道路網（`data/komoro.json`、交差点 約1.7万・道 約2.3万本）を読み込みます。徒歩・自転車・車ごとに、通れる道と向きを決めます（車は歩道・小道・林道を通らず、一方通行を守る。徒歩・自転車は高速道路を通らない。自転車は階段を通らない）。
2. 掲示場と出発地点を、いちばん近い道の上の点に吸着させます（400m 以内。車は、どこからでも行き来できる道にだけ吸着させる）。
3. ダイクストラ法で、すべての組の道に沿った最短距離の表を作ります（150か所で約0.2秒）。車は一方通行のため、行きと帰りで距離が違うことがあります。
4. その表で、下の方法でルートを解きます。
5. 決まった順番の区間ごとに、道に沿った線を作って地図に描きます。

道から400m以上離れた掲示場は、直線距離×1.3で見積もり、画面で知らせます。

小諸市の市街地で試すと、道に沿った距離で解いた順番は、直線距離で解いた順番より、実際の道のりが徒歩で1〜10%、車で4〜19%短くなりました（掲示場が多いほど差が大きい）。

### 回る順番（`js/tsp.js`）

| 掲示場の数 | 方法 |
| --- | --- |
| 12か所以下 | 動的計画法（Held-Karp）で、**最短の順を厳密に**求めます |
| 13か所以上 | 最近傍法で作った順を、2-opt（2本の辺のつなぎ替え）と Or-opt（1〜3か所の移し替え）で縮め、さらに反復局所探索（ダブルブリッジで崩して縮め直す）を時間の許すかぎり（約2.5秒まで）繰り返します |
| 班に分けるとき | 全体を回る輪を作ってから、順番のまま区切ります。区切り方は、いちばん重い班（移動＋作業の時間）が最小になるように動的計画法で決め、班ごとに順番を縮め直します |

- 最後に出発地点へ戻らないときは、「どこで終えてもよい」道順として解きます。
- 行きと帰りで距離が違うとき（車の一方通行）は、厳密に解くときはその向きのまま、近似のときは往復の平均で探してから、実際の向きの距離で数え直し、逆回りのほうが短ければそちらを選びます。
- 参考にした掲示場巡回 PWA の方法（最近傍法＋2-opt）と比べると、乱数で作った100〜1,000か所で、道のりが6〜11%ほど短くなりました。

### 注意

- 道路データは OpenStreetMap のもので、実際の道と違うことがあります（新しい道がない、通行止めが反映されていない、など）。信号・坂・右折のしにくさは考えていません。
- 時間は、道のりを徒歩4km/h・自転車12km/h・車20km/hで割り、作業時間を足した目安です。
- 13か所以上のときは、最短の順だという保証はありません（十分に短い順です）。
- 道路データは、小諸市の範囲より約1km広い四角の中だけです。小諸市の外の掲示場には向いていません。

## データとプライバシー

- **一覧・出発地点・貼った記録は、この端末のブラウザの中（localStorage）だけに保存します。** サーバーには送りません。ブラウザのデータを消すと、すべて消えます。
- 端末の外とのやり取りは、次のとおりです。
  - **Google マップ**: 「案内」を押すと、目的地（と経由地）の位置が Google マップに渡ります。
  - **国土地理院**: 地図を表示するとき、見ている範囲の地図画像を取得します。
  - 道路データはこのアプリと一緒に配信するもので、道に沿った距離の計算は端末の中で行います。掲示場の位置を外に送ることはありません。
  - **国土地理院の住所検索**: 出発地点・終点の「探す」を押すと、入れた言葉（頭に「長野県小諸市」を付けたもの）を国土地理院に送り、住所の位置を調べます。打っている間の候補は、同梱の一覧から端末の中で出します。
  - **unpkg**: 地図の部品（Leaflet）を取得します。
  - 「順番を送る」は、端末の共有機能かコピーを使います。送り先を選ぶまで、どこにも送りません。

## 掲示場データについて

このリポジトリには、**架空の見本データ（小諸市内の30か所。位置は道のそばに置いた架空のもの）だけ**を入れています。実際の掲示場の一覧は、各自治体の選挙管理委員会が公開する資料やオープンデータから入手し、利用条件と出典の表示に従って取り込んでください。掲示場は選挙ごとに変わります。

## 使うときの注意

- **運転中は操作しないでください。** 停車してから、または同乗者が操作してください。
- 選挙での利用にあたっては、公職選挙法などのルールを守ってください。

## 開発

ビルドは不要です。ファイルをそのまま配信すれば動きます（位置情報とオフライン対応は HTTPS か localhost でだけ動きます）。

```bash
npm start   # http://127.0.0.1:8782
npm test    # 試験（Node 22 以上）
```

| ファイル | 中身 |
| --- | --- |
| `index.html` / `style.css` | 画面の枠と見た目 |
| `js/app.js` | 画面（準備・ルート・班ごとの巡回・地図・CSV の取り込み） |
| `js/tsp.js` | ルートの計算（巡回セールスマン問題・班分け） |
| `js/roads.js` | 道に沿った距離（道路網・吸着・ダイクストラ法・道に沿った線） |
| `js/places.js` | 出発地点・終点を名前や住所で探す |
| `js/solve.js` / `js/worker.js` | 計算の入口と、それを画面と別に動かす Web Worker |
| `js/plan.js` | 所要時間の見積もり・送る文字など |
| `js/core.js` | CSV の読み込み・列の割り当て・行の検査・Google マップの URL |
| `js/store.js` | 端末内の保存 |
| `data/komoro.json` / `data/komoro-boundary.json` / `data/komoro-places.json` | 小諸市の道路網・境界・場所の名前（`tools/build-komoro.mjs` で作成） |
| `sw.js` / `manifest.webmanifest` / `icons/` | オフライン対応とホーム画面への追加（アイコンは `tools/make-icons.mjs` で作成） |

### 道路データを新しくする

1. `node tools/build-komoro.mjs` を引数なしで実行すると、Overpass API に送る問い合わせ（道路と境界）が表示されます。
2. それぞれを [Overpass API](https://overpass-api.de/) に送り、結果を roads.json・boundary.json・places.json として保存します（公開サーバーは混み合うことがあるので、時間をおいて試してください）。
3. `node tools/build-komoro.mjs roads.json boundary.json places.json` で `data/` の3つのファイルを作り直し、`sw.js` の `VERSION` を上げます。
